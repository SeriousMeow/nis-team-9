# Описание проекта

## Назначенное задание

[P31-A. GC3: корректность расписаний](https://distsys.ru/osukhoroslov/nis2/src/branch/main/project-tasks/p31-a-gc3-correctness.md)

## Выбранный технический путь

Авторский артефакт + симулятор

## Что будет сделано и как это проверить

- Написать программы ring AllReduce и AllToAll на MSCCLang и проверить, что они компилируются в XML-расписания для нескольких значений числа GPU.

- Реализовать независимое вычисление ожидаемых выходных буферов непосредственно по входным данным: для AllReduce сложить соответствующие блоки, для AllToAll распределить блоки по получателям. Этот результат использовать как эталон при проверке исполнения XML-расписаний.

- Разработать CPU-симулятор XML-расписаний, который моделирует выполнение инструкций и зависимости между ними. Проверить, что на корректных расписаниях конечные буферы совпадают с независимо вычисленным эталоном.

- Подготовить положительные примеры и не менее трёх намеренно испорченных расписаний. На них проверить обнаружение потерь, дублирования, чтения до записи и взаимоблокировок.

- Настроить пайплайн для автоматической генерации и проверки расписаний для нескольких размеров топологии. Сравнить состав инструкций и модельное время выполнения с выбранным эталонным расписанием. Сохранить результаты экспериментов, проанализировать различия и объяснить полученные выводы в отчёте.

## Поддерживаемые сценарии

Рассматриваются XML-расписания коллективных операций между GPU, выполнение которых моделируется на CPU. Входные данные целочисленные, операция AllReduce — сложение.

Для ring AllReduce каждая GPU получает входной буфер с одинаковым числом блоков. После выполнения на каждой GPU должен находиться одинаковый результат — поэлементная сумма соответствующих входных блоков всех GPU.

Для AllToAll каждая GPU получает блоки, предназначенные для разных получателей. После выполнения каждая GPU должна получить предназначенные ей блоки от всех отправителей с сохранением их содержимого и ожидаемого расположения в выходном буфере.

Для обоих алгоритмов рассматриваются корректные и намеренно испорченные расписания. На корректных расписаниях выполнение должно завершаться с результатом, совпадающим с независимым эталоном. На испорченных расписаниях проверяется обнаружение потерь, дублирования, чтения до записи и взаимоблокировок.

## Упрощения

Время считается в условных тактах, а не в реальных секундах. Цены операций задаются вручную и не калибруются по конкретному оборудованию, поэтому расписания сравниваются между собой, а не предсказывается абсолютное время.
